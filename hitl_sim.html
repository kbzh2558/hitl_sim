Formulation: two interfaces, one human model

Formulas need an internet connection to display (they use the KaTeX library); without it they show as raw TeX. The simulator itself works offline.

Setup A and Setup B share the same underlying human decision-making model. They differ in how alternatives are generated and presented, not in how the human evaluates them or makes mistakes. Otherwise, if the two setups used different error mechanisms, we could not tell whether their different convergence comes from decision complexity, from the available alternatives, or from the human-error assumptions.

1. World and features

Each month $t$, cargoes must be assigned to feasible ships; $X_t$ is the set of feasible assignments. The planner's true objective is linear in known, possibly nonlinear, features of the assignment:

$$F_t^\star(x)=c^{\star\top}\phi_t(x),\qquad x_t^\star=\arg\min_{x\in X_t}F_t^\star(x).$$

$\phi_t(x)$ adds up features of the individual cargo–ship matches in $x$, so every objective stays a sum over the chosen matches.

The features built in this simulator (show / hide)

Familiar features (in this order): waiting days, sailing cost, lateness, empty-trip distance, spare capacity, destination match, preferred operator, unwanted region pair. Their true weights: a fixed sign × a random size between $\underline w$ and $\bar w$, scaled to the cost unit.

Nonlinear features (each built per cargo–ship match from attributes the machine sees, then added up over the assignment):

A plausible but wrong feature. Special cargo on a ship whose next region is not its destination: $\sum_{i,j}\mathbf{1}\{\text{special } i\}\,(1-\text{destination match}_{ij})\,x_{ij}$. Its true weight is 0; the machine starts with weight $P_0$ = on it. For special cargo, close ships tend to have destination match and premium service together; distant ships less so.

Thresholds $\tau_w$, $\delta_b$ and the true weights are set on the World Features Parameters tab. Cost unit: 1 = the cost change of one typical small reassignment on the familiar features.

2. One process, two ways of building the decision set

$$\boxed{\widehat c_t\;\longrightarrow\;S_t(h)\;\longrightarrow\;\text{human comparisons}\;\longrightarrow\;x_t^H\;\longrightarrow\;\widehat c_{t+1}}$$

$S_t(h)$ is the set of alternatives the human actually evaluates, and $h$ is the complexity the interface allows. The machine's plan is always in it:

$$q_t=\arg\min_{x\in X_t}\widehat c_t^{\top}\phi_t(x).$$

The critical distinction is between candidate generation and candidate evaluation. In Setup A the human generates the modifications; in Setup B the machine generates the alternatives and the human only compares them. That may change how much preference information the human can reveal, even when evaluation accuracy is identical.

Setup A: modify

The radius-restricted feasible set $\mathcal B_t(q_t,r)=\{x\in X_t:D(x,q_t)\le r\}$, with $D$ the number of cargoes assigned differently, is not the set the human examines. The human examines

$$S_t^A(r)\subseteq\mathcal B_t(q_t,r),$$

the plans visited by a feasible local-search process starting at $q_t$. In the simulator each edit moves one cargo to an idle allowed ship or swaps two cargoes, is drawn at random without using the true weights, and must stay within radius $r$ of $q_t$. The human visits up to $m_A-1$ edits:

  • Sequential procedure: each edit is made to the current incumbent and compared with it (local search).
  • Tournament procedure: each edit is a random walk of 1 to $r$ moves from $q_t$; then one bracket.

The truly best plan within the radius, $\min_{x\in\mathcal B_t(q_t,r)}F_t^\star(x)$, is computed exactly but only as a diagnostic.

Setup B: choose

The machine's near-optimal region is

$$\boxed{\mathcal N_t(\varepsilon)=\left\{x\in X_t:\widehat F_t(x)\le\widehat F_t(q_t)+\varepsilon\right\}.}$$

The simulator lists every plan in $\mathcal N_t(\varepsilon)$ in one ranked enumeration (capped at $K_{\max}$ plans; if the region is larger, it keeps the $K_{\max}$ best). It then draws $k-1$ of them uniformly at random without replacement:

$$S_t^B(k)=\{q_t,q_t^2,\ldots,q_t^k\}.$$

Menus are nested: one random order per month is used for every $k$, so a larger menu adds plans and keeps the earlier ones. Hence, at a fixed model state, the best available plan cannot get worse as $k$ grows; only the human's ability to pick it can.

Uniform sampling matters. Taking the $k$ best plans may return near-copies of $q_t$ and never expose, say, the special-cargo preference. A uniform draw from the whole region has a chance of including a plan that is informative about a weight the machine set to zero.

3. One human comparison model

One primitive operation:

$$\boxed{\mathcal H_\eta(x,y)=\text{the human's chosen plan when comparing }x\text{ and }y.}$$

The human tries to select $\arg\min_{z\in\{x,y\}}F_t^\star(z)$, but the comparison can be wrong:

$$\Pr\bigl(\mathcal H_\eta(x,y)\ne\arg\min_{z\in\{x,y\}}F_t^\star(z)\mid\text{history}\bigr)\le\eta.$$

The simulator uses independent errors with probability exactly $\eta$ (equally good plans: either one). The same oracle and the same procedure (sequential incumbent or balanced tournament, $|S|-1$ comparisons either way) evaluate the set in both setups:

$$\boxed{x_t^H=\mathcal H_\eta\bigl(S_t(h);c^\star\bigr),\qquad z_t(h)=\arg\min_{x\in S_t(h)}F_t^\star(x).}$$
  • In Setup A, $r$ affects which modifications are encountered, how different they are, and how many comparisons the human makes.
  • In Setup B, $k$ directly sets how many alternatives are compared.
  • In both, the same oracle decides whether the human errs. Human error depends on the comparison task, not on which interface produced it.

Random-choice control: $\eta=0.5$ (coin-flip comparisons). Any improvement it shows is not learning from the human.

Extension (not yet implemented): a constant $\eta$ says that comparing two very different plans is no harder than comparing two nearly identical ones. A common difficulty-dependent bound would be $\Pr(\text{error}\mid x,y)\le\eta\bigl(D_t(x,y)/n_t,\;|F_t^\star(x)-F_t^\star(y)|\bigr)$, which also applies to both interfaces.

4. The machine

The machine's objective uses the same 12 features with wrong weights: $\widehat F_t(x)=\widehat c_t^{\top}\phi_t(x)$. At the start, the first $d$ of the 11 true features have wrong weights, the other $11-d$ have weight 0, and the wrong feature has $P_0$. The wrong weights are the true ones turned away in a fixed random direction until the starting plan's regret equals $R_0$. Every run of a replicate starts from exactly the same $\widehat c_0$, whatever the setup, $h$ or $\eta$, and uses the same random numbers.

The same update is used in both setups. It is a structured margin loss that asks the human's plan to beat every feasible plan:

$$\mathcal L_t(\widehat c)=\max_{x\in X_t}\Bigl[\widehat c^{\top}\phi_t(x_t^H)-\widehat c^{\top}\phi_t(x)+\mu\,D(x_t^H,x)\Bigr].$$

It is minimized over all months so far by $E$ passes of Adam, with the weights rescaled after each step to the truth's cost spread (rescaling changes no decision). When the hardest competitor is $q_t$, the step is along

$$g_t=\phi_t(x_t^H)-\phi_t(q_t).$$

5. The common learning relationship

Because $q_t$ is optimal under $\widehat c_t$, we have $\widehat c_t^{\top}g_t\ge0$, so for every response, correct or not:

$$\boxed{\mathbb E\bigl[(\widehat c_t-c^\star)^{\top}g_t\bigr]\ge\underbrace{F_t^\star(q_t)-F_t^\star(z_t(h))}_{V_t(h):\ \text{potential improvement}}-\underbrace{\mathbb E\bigl[F_t^\star(x_t^H)-F_t^\star(z_t(h))\bigr]}_{\beta_t(h):\ \text{response error}}.}$$

This needs no knowledge of whether $h=r$ or $h=k$. The interface matters only through the distribution of $S_t(h)$, which determines the potential improvement, the feature differences available, and the comparison difficulty.

Diversity in feature space. Two assignments can differ in many cargoes yet be nearly identical in features, and one special cargo moved from a basic to a premium ship can be highly informative. With $v_t(x)=\phi_t(x)-\phi_t(q_t)$, the simulator reports how many preference directions a set exposes:

$$M_t(S_t)=\sum_{x\in S_t}v_t(x)v_t(x)^{\top},\qquad \text{directions exposed}=\frac{(\operatorname{tr}M_t)^2}{\|M_t\|_F^2}.$$

This describes the candidates, not the information the learner receives: it observes only the winner. Useful information combines the preference differences exposed with the reliability of the human's choices. A large, diverse menu with mostly wrong comparisons can be less useful than a smaller, reliable one.

$r$ and $k$ are not comparable measures of complexity, so the two setups are compared through these common measures. With $m_A=k$, both interfaces have the human evaluate the same number of plans with $m-1$ comparisons, under an identical decision mechanism; only the distribution of alternatives differs.
